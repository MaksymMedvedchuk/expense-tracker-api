# Опис PR

## Кроки

1. Подивись зміни гілки відносно `main`:
    - `git log main..HEAD --oneline` — список комітів;
    - `git diff main...HEAD --stat` — які файли змінено;
    - `git diff main...HEAD` — самі зміни (для великих диффів читай вибірково).
2. Знайди номер задачі (TASK-xxx, STORY-xxx) у назві гілки або комітах. Якщо є — постав першим рядком: `TASK-005 (STORY-002): <коротка назва>`.
3. Якщо я вказав задачу текстом (опис, acceptance criteria) — звір із нею, що зроблено, а що ні.
4. Заповни шаблон нижче.
5. Покажи готовий опис у markdown-блоці і дочекайся мого погодження.
   Після погодження — `gh pr create` (або `gh pr edit`, якщо PR для гілки вже існує).

## Правила

- Пиши українською, коротко і конкретно. Без загальних фраз на кшталт «покращено якість коду».
- **Що** — список змін по суті, а не по файлах. Назви класів і файлів — у `code`.
- **Чому** — посилання на задачу/вимогу і причини технічних рішень (чому саме так, а не інакше).
- **Як перевірити** — конкретні кроки: команди (`./gradlew build`, `./gradlew test`, curl-запити) і очікуваний результат. Якщо є негативна перевірка (що має впасти) — додай її.
- **Чого свідомо не зроблено** — що логічно було б зробити, але винесено за скоуп, і чому. Не вигадуй: якщо нічого — напиши «—».
- Якщо чогось не можеш визначити зі змін (наприклад, причину рішення) — не вигадуй, а залиш `<!-- TODO: ... -->` і скажи мені про це після тексту.

## Шаблон

```markdown
<TASK-xxx: назва, якщо є>

## Що

-

## Чому

-

## Як перевірити

1.

## Чого свідомо не зроблено

-
```
